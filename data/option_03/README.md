# Option 3. Planning delivery routes

option-3-brief.pdf defines this option's decision, constraints, required output, measures, rule to beat, reading, and stress-test input. The project guide (team-project-guide.pdf) defines what every decision tool must do, the milestones, the grading rubric, and the run the instructor performs. DATA_DICTIONARY.md defines every input column for this option. Each instance directory contains its own CSV inputs, schema.json (column types and which columns may be empty), and instance.json (time unit and the condition the instance tests). Paths are relative to this folder.

Begin with hand_checkable/ and worked-example/, which applies the option's rule to beat to the hand-checkable case and recomputes every measure except computation time. Reproducing those values is a useful first test of a loader and checker, and worked-example/solution.json shows the structure of the decision.json file that the instructor's checker reads. The example is not an optimal answer. Use development_small/, development_medium/, and development_large/ for comparisons, and edge_case/ to test the documented infeasible, malformed, or empty condition. The instructor keeps a separate held-out case of size 60 for grading. Preserve these inputs and write results to a separate output directory.
